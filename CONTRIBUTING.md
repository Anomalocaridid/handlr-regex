# Contributing to handlr-regex

Thank you for considering contributing to handlr-regex!

If you believe that this file is missing relevant information or is otherwise unclear, please feel free to make an issue or pull request.

## Development Guide

### Prerequisites
  - [rust](https://rust-lang.org/)
  - [cargo](https://github.com/rust-lang/cargo)
  - [rustfmt](https://github.com/rust-lang/rustfmt)
  - [clippy](https://github.com/rust-lang/rust-clippy)
  - [cargo-mutants](https://mutants.rs/)
  - [cargo-insta](https://insta.rs/)

Furthermore, it is highly recommended to use a text editor or IDE that supports the [Language Server Protocol](https://langserver.org/) and configure it to use [rust-analyzer](https://github.com/rust-lang/rust-analyzer) and clippy for code linting.

Alternatively, users may install [nix](https://nixos.org/) and run `nix develop` to create a temporary development environment with all of the dependencies listed above.

### Guidelines
  - Use [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/) to format commit messages.
  - If adding a new feature or otherwise significantly changing behavior, please add regression tests.
  - Ensure `cargo mutants` does not report any missed mutants. If there are, then add or update tests as needed if feasible. If it is not feasible or practical, annotate the relavent functions with `#[mutants::skip]` and add a comment explaining why testing them is infeasible or impractical.

### Example Workflow

Note, the steps shown below are mainly for illustrative purposes.

  1. Clone and enter git repository
  1. If using nix, run `nix develop`
  1. Make and test changes
  1. Add or modify tests if applicable
  1. Test changes for regressions with `cargo insta test`
  1. Check code coverage with `cargo mutants` (Note: this will take a while)
  1. Make further changes and repeat steps as necessary
  1. Create pull request

## AI-generated Contributions

Contributions must not include any content generated by large language models or any other probabilistic tools.

This includes, but is not limited to, code, documentation, assets, commit messages, and issue/PR/discussion text.

Any issues or PRs containing such content may be closed without further consideration.

Adding dependencies that contain AI-generated content is discouraged and should be avoided when feasible.

For explanation as to why, see [Why not LLMs?](https://codeberg.org/small-hack/open-slopware#why-not-llms)
